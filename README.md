# ✅ To-Do 리스트

할 일을 빠르게 기록하고, 우선순위와 마감 일시를 지정해 관리하는 반응형 To-Do 리스트입니다. 할 일의 추가·조회·수정·삭제와 완료 상태별 필터링을 지원하며, 브라우저 `localStorage`에 저장해 다시 방문해도 목록을 유지합니다.

## 주요 기능

- 할 일 내용, 마감 일시, 우선순위를 입력해 추가
- 전체·진행 중·완료 탭과 각 상태별 항목 수 표시
- 완료 체크 및 전체 진행률 표시
- 할 일 인라인 수정과 취소, 사용자 확인 모달을 통한 삭제
- 완료 체크 시 꽃가루 효과
- 공백 입력 방지, 긴 문장 말줄임, 빈 목록 안내
- HTML 태그를 실행하지 않는 안전한 텍스트 렌더링
- 저장소 오류 발생 시 안내 후 현재 세션에서 계속 사용
- 모바일과 데스크톱 화면에 대응하는 레이아웃

## 어떻게 만들었나요

1. 기능과 예외 상황, 데이터 구조, 화면 구성, 완료 기준을 [PRD.md](./PRD.md)에 정리했습니다.
2. 구현 전에 PRD의 완료 기준을 기준으로 계획을 세우고, 기능과 화면을 구현했습니다.
3. HTML·CSS·Vanilla JavaScript로 동작하도록 구성하고, 할 일 목록의 이벤트 위임과 `textContent` 기반 렌더링을 적용했습니다.
4. 완료 기준을 확인한 뒤 꽃가루 효과와 삭제 확인 모달을 추가해 사용 경험을 보완했습니다.

## Bootstrap vs Tailwind

이 작업본은 **Tailwind CSS 버전**입니다. [guide.md](./guide.md)의 실습 흐름에 따라 같은 PRD를 기반으로 Bootstrap과 Tailwind 버전을 비교하도록 구성되어 있지만, 이 저장소의 현재 작업본에는 Tailwind 구현만 포함되어 있어 두 버전의 화면을 직접 대조한 결과는 기록하지 않았습니다.

구현 방식으로 보면 Bootstrap은 준비된 컴포넌트 및 의미 중심 클래스를 조합하는 방식이고, Tailwind는 간격·색상·레이아웃 같은 유틸리티 클래스를 HTML에 조합해 화면을 구성하는 방식입니다. 이 버전에서는 원하는 반응형 레이아웃과 세부 스타일을 직접 조정하기 쉬워 Tailwind를 사용했습니다.

요청에 따라 Tailwind CSS를 CDN으로 불러오며, PRD의 외부 CSS 라이브러리 미사용 원칙은 이 버전에 한해 적용하지 않았습니다. Tailwind의 브라우저 CDN은 빌드 없이 실행할 수 있지만, 공식 문서상 개발·학습용입니다. 실제 서비스 배포에는 빌드 방식 사용을 권장합니다.

## 실행 방법

저장소 루트에서 간단한 정적 웹 서버를 실행합니다.

```bash
python3 -m http.server 8000
```

브라우저에서 <http://localhost:8000>을 엽니다. Tailwind 스타일을 불러오려면 인터넷 연결이 필요합니다.

GitHub Pages 배포 주소는 <https://leetaewon.github.io/26-w08-todo/>입니다. 현재 이 주소는 사용자 지정 도메인으로 이동하지만, 해당 도메인에서 이 프로젝트 페이지를 찾을 수 없어 배포 페이지를 확인할 수 없습니다. Pages 설정과 배포를 완료한 뒤 주소를 다시 확인해 주세요.

## 커스터마이징한 부분

- 완료 항목을 체크하면 색종이가 퍼지는 꽃가루 애니메이션을 추가했습니다. 사용자의 동작 줄이기 설정이 켜져 있으면 애니메이션을 생략합니다.
- 삭제 버튼을 누르면 브라우저 시스템 확인창 대신 자체 모달을 표시합니다. 삭제할 항목을 확인할 수 있고, 취소 및 확인 버튼으로 동작을 선택합니다.
- 삭제 모달의 아이콘은 금빛 장식과 슬픈 얼굴을 조합해 새로 구성했습니다.
- 모바일 화면에서 입력 폼을 한 열로 배치하고, 주요 조작 요소의 터치 영역을 44px 이상으로 설정했습니다.
- 긴 할 일은 최대 두 줄로 말줄임 처리하고, 전체 내용은 기본 툴팁으로 확인할 수 있게 했습니다.

## 기술 구성

- HTML5
- Tailwind CSS Browser CDN 및 보조 CSS
- Vanilla JavaScript (ES6+)
- 브라우저 `localStorage` (`MY_TODO_APP_DATA_V1`)

자세한 실습 순서는 [guide.md](./guide.md)를 참고하세요.
